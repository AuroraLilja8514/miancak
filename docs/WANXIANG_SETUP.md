# Wanxiang setup after installation

The download candidate keeps MIANCAK's engine, all pinned Wanxiang Lua and runtime configuration, the small compatibility vocabulary, and the original licenses in the APK. Setup downloads the remaining Wanxiang Base data and the Simplified Chinese grammar. The candidate pins a newer official grammar. The frozen v0.3.3 APK contains the earlier grammar and the full Base.

## Set up Chinese input

Open **Chinese input setup** from the launcher or MIANCAK Settings. If the exact pack is already installed, the screen reports ready and skips transfer. Otherwise **Download** starts an explicit 416,983,665-byte transfer. English and literal input work on a fresh install before setup. If the earlier verified pack is present, Chinese input can continue offline while the new download is unavailable, in progress or cancelled. After the resource check and first compilation complete, use the keyboard language key to switch to Chinese. Ordinary typing and later restarts use local files.

You can cancel the transfer or leave the screen and return to complete setup. The screen shows separate transfer, unpacking and compilation states. A retry starts a new transfer. An interrupted install never exposes incomplete resources to the engine. Keep sufficient free storage for the verified resources, the temporary Base ZIP and the compilation reserve. Initial Android setup and model load timings still need measurement.

If the exact transfer is unavailable, **Install from verified files** uses the standard Android file picker. Select the original Base ZIP and then the matching `.gram`. Both files still have to pass the same size, SHA-256 and archive checks. MIANCAK verifies a real candidate through the offline engine using a disposable user directory before activation. Existing imported YAML, selection history, keyboard layouts and learning remain in their original locations. A damaged pack at the same identity is preserved when repaired. Data from older vocabulary can remain active through the existing recovery route.

## Verification

`python3 scripts/prepare_rime.py` generates the APK asset directory without fetching the model. `--with-runtime-fixture` verifies and stages the exact model for host tests and caches it under `.native/wanxiang-downloads/model-763629573/`. The earlier cache file remains available for its own lock. `scripts/check_native_apk.py` checks the packaged overlays and the download plan. For guarded offline Android testing, set `MIANCAK_WANXIANG_FIXTURE_DIR` to a directory containing matching `base-v18.1.13.zip` and `wanxiang-lts-zh-hans.gram` files. The driver checks both pins before copying them to the disposable guest. The fixtures and any guest logs, screenshots or user data stay outside published evidence.

On Android 15+, use separate targets for the two fresh entry orders and the overwrite. The exact-manifest case should skip transfer. On the current changed-manifest fixture, verify the earlier pack works offline while the update is unavailable or interrupted. Check actual Chinese input, original YAML and learning before activating the new pack, then verify reuse after reboot. Keep live HTTPS transfer, cancellation, corrupt file and storage exhaustion as distinct cases. The formal signed upgrade still needs its own verified inputs and Android evidence. See the [private runbook](ANDROID_ACCEPTANCE_RUNBOOK.md) and [Wanxiang acceptance](WANXIANG_ACCEPTANCE.md).
