# Rime 词表管理（#22）

本轮开发以此契约为准；完成状态与实际 APK 验收记录在对应 PR 中。词表管理独立于布局 JSON、完整第三方方案和 cdict 格式迁移。

## 里程碑

1. W1：发布数据配置、流式校验、内容寻址导入目录和依赖解析；无效导入不得部分修改目录。
2. W2：基础／附加词表设置、明确应用、后台编译、输入队列维护事务、版本化部署和失败恢复；沿用稳定的个人学习目录。
3. W3：两套现有词表的真实候选差异、附加表开关、实际正文、文件选择器、进程／设备重启与真实 APK 覆盖升级；通过全部适用检查再合并交付。

## 支持的数据配置 v1

- UTF-8（允许 BOM）的 `.dict.yaml`，以 `---` 开始表头、`...` 结束表头；数据列使用 Tab。支持注释、普通／单引号／双引号标量，以及行内或分行的 `columns`／`import_tables` 列表。
- 必须有 `name`；支持 `version`、`sort: by_weight/by_original`、`columns`、`import_tables`、`use_preset_vocabulary`。不接收其他配置键、YAML 标签／锚点、方案、脚本或模型。
- 默认为 `text, code, weight`；也接受列顺序调整、仅 `text, code` 和空的 `stem`。每行必须有文字及明确的输入码。不支持无注音的词频表、非空造词码、预设 essay 词频和自动注音。
- 词条最多 256 个 Unicode 码点。输入码为小写 ASCII 字母组成的音节，每个音节 1–8 个字母，以空格分开，使用 `v` 表示需要时的 ü；不导入声调数字、带调拼音、双拼／形码方案或辅助码规则。文件校验只能检查字符结构，不能证明词条的实际读音。
- 权重为不超过 10¹² 的非负有限数；缺省权重为 1。使用预设词频的配置或百分比权重须先转换为明确权重。`by_original` 按原顺序转换为 `10⁹ / 词条序号` 的明确权重。
- 每个文件上限 64 MiB、单行 16 KiB、表头 64 KiB；最多 64 张表，原始导入总量上限 256 MiB。采用流式处理，不把整张表放入 Java 内存。
- 依赖通过 `import_tables` 声明；相对目录引用按最后一段匹配唯一的声明名称。禁止绝对路径、父目录、反斜线、循环和缺失依赖。可分次导入依赖，应用时才要求依赖完整。
- Android 文件选择器可多选原始词表。压缩包应先解压。每张表保留原始文件、SHA-256、声明名称／版本、来源文件名和注释；同名不同内容需先切换离开并移除旧表。

## 输入与部署

导入只增加目录中的可选数据。基础表、附加表和开关在点击“应用词表”后才生效；恢复内置表也是一次明确应用。删除不能破坏当前使用的基础表、附加表及其依赖。

应用先在现有串行队列中确认当前组词，暂停接受新的键盘输入，关闭旧会话，再在独立版本目录合并和编译词表。仅使用程序生成的配置和经过校验的条目，保留 MIANCAK 的方案、标点、手势及候选逻辑。编译和会话验证成功后才原子替换活动指针；失败继续使用上一套表。切换完成后重建当前编辑器代次，使旧候选和旧回调失效。

版本目录隔离编译产物；个人学习继续使用原 `rime/user` 和 `pinyin_simp` 用户词典标识。词表管理不清空学习库或布局偏好。保留活动版本和上一可用版本，清理更旧的受管理产物。损坏／丢失的部署应恢复上一可用版本或内置表，并在管理页面显示恢复情况。

基础词表应包含相应的单字音节表，可通过依赖组合；纯词语表建议作为内置或其他完整基础表的附加表。Rime 编译或候选验证失败时保留旧选择。确认操作先确认当前候选，再提交；空闲状态完成学习事务，避免直接提交绕过 Rime 的已确认片段通知。隐私字段仍使用不学习方案。

## 验收与来源

需要单元校验、真实 librime 候选／学习测试、普通 Android 文件选择和输入正文测试，不能以复制文件成功代替实际输入。测试使用锁定的 rime-pinyin-simp 和 rime-ice 数据以及明确标记的本项目附加表；实际版本、哈希及许可随测试数据记录。测试数据不成为默认生产词表。

跨语言共同格式及 cdict 转换继续由 #18 跟踪。第三方完整方案、自动抓取 MediaWiki、词条编辑器和同步服务不属于本轮。
