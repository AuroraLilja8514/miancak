# 独立词典项目立项方案

更新：2026-10-27。范围：规划并准备独立仓库，不实现转换器／采集器，不修改 miancak 应用。创建结果：本轮尚未创建远程仓库；五份初始化文档已准备并打包，没有转换器／采集器实现。后续实际创建成功时再更新仓库地址和状态。

## 数量与名称

现在只建 **一个**独立项目：`rime-lexicon-tools`（建议在 AuroraLilja8514 账号下创建，初始私有）。它同时容纳词源适配／采集、格式转换、共同校验和打包模块，不拆成互相重复处理词条的多个工具仓库。

以后按实际需要再建 **第二个**项目：`rime-lexicon-packs`。仅在已有可重复构建的词包、来源许可清单，并出现持续独立的数据更新或其它消费者时建立。它管理数据版本和发布清单，不管理 Android 输入界面。本次不创建这个候选仓库。

miancak 继续作为原有应用项目；因此现在是“miancak + 一个新工具项目”，不是立即扩张为三个新增项目。

## rime-lexicon-tools 的职责

| 模块 | 工作 | 明确边界 |
| --- | --- | --- |
| sources | 从可追溯源词表或 MediaWiki 导出／API 读取词源，保留修订和许可信息 | 首个 MediaWiki 试点优先处理本地合成导出；联网适配以后再实现，不在导入输入法时抓取网站 |
| converters | 把 cdict 上游源词表等转为声明的 Rime 兼容源文件，记录输入编码、权重及不支持字段 | 不能将 cdict 二进制改名为 Rime 文件；无法恢复的字段须报告，不宣称无损 |
| profiles／validation | 定义版本化数据子集，校验 UTF-8、列、编码、重复、依赖和资源限制 | 单一格式不等于任何语言、任何 Rime schema 都能工作；没有拼音的中文词条不能冒充显式拼音格式 |
| packaging | 形成确定性的词表／manifest／来源和许可清单，记录字节哈希 | librime 与 cdict 编译结果是各自后端产物；是否生成某个后端产物单独立项，不把它们当共同源文件 |

目标是命令行工具加可复用库；建议先用 Python 实现文件处理核心，具体最低版本、依赖与许可证在首个实现 PR 中确定。当前只初始化文档，不交付可运行命令、不拉取第三方词库、不发布安装包或定时抓取任务。

## 实施里程碑

| 顺序 | 工作 | 验收 |
| --- | --- | --- |
| T0 | 数据契约与来源清点 | 明确词条文本、编码、权重、重复／排序、Unicode／大小写保留、依赖与元数据；把不支持的字段、许可和歧义列出来 |
| T1 | 一个英语源词表的离线转换试点 | 先选定允许使用的固定来源及其实际字段；相同输入和配置重复生成相同字节，词条／大小写／权重映射可追溯，异常有具体诊断。先用合成小样测试，不直接承诺英文联想或纠错 |
| T2 | MediaWiki 词源试点 | 从本地导出提取少量词条，覆盖命名空间、重定向、消歧、清洗与来源。没有可靠读音／词频的数据明确保留缺失状态或进入待审清单；实际网站抓取另定参数和范围 |
| T3 | 可复用打包与端到端验证 | 固定工具和源版本、清单及哈希；损坏／缺依赖／中断不覆盖已有产物。用声明支持的引擎配置实际查询，并在 miancak 通过既有支持格式导入、输入、重启及恢复 |
| T4 | 评估抽出数据仓库和扩展语言 | 依据真实更新和复用需求决定是否建 rime-lexicon-packs；扩展一个带重音拉丁语言，逐项记录数据映射与后端能力，不能按词表数量推断多语言输入已完成 |

T1 的数据转换验收与英文输入功能验收分开。英文前缀、拼写纠错、候选交互以及其它语言的输入算法是 miancak／引擎集成工作；直接英文输入继续可用。

## 数据契约草案

共同维护的源以 UTF-8 Rime 兼容 `.dict.yaml` 为方向，profile 是工具声明的子集。旁路 manifest 至少考虑：

- 格式／profile 版本、词包 ID 与版本、语言／地区、编码配置；
- 每个输入源的 URL、固定修订、哈希、许可标识／原文及必要署名；
- 转换工具版本、参数、修改说明、字段映射和不支持项；
- 输出路径／哈希、条目数、依赖与资源限制。

具体字段名、schema、校验策略在 T0 确认。profile／语言与 schema 区分，不允许从路径或隐藏状态猜测编码。保留上游原始输入或可重现获取方式；不静默删除无编码行、多音词、大小写或无法映射的元数据。

## 与 miancak 的接口

工具输出可校验的数据与诊断，miancak 负责现有兼容词表的正常 DocumentsUI 导入、选择／附加开关、离线编译部署、候选、个人学习和失败恢复。用户仍可直接导入已有兼容词表，不强制安装或运行本工具。

涉及新增 profile 或语言行为时，先扩展并验收应用支持范围，再宣传兼容；不自动更换当前雾凇默认词包，不要求完整万象方案／Lua／模型。输入法不上传个人学习给工具或共享数据仓库。

主应用自身的修复、质量与交付路线不依赖这个项目完成；H1 仍在 miancak 内后置讨论，Compose 不变。

## 开发与测试约束

每个实现 PR 才引入适用检查：可重复输出、Unicode／编码、权重／重复、坏文件、缺依赖、资源上限、原子输出及具体错误信息。联网适配实现后再补重试、限速、恢复和本地假服务测试。

所有脚本／命令须提供可配置的有限总超时（默认可用 3600 秒），网络调用另设有限超时，测试不得无限等待。不以大规模在线抓取作为日常 CI；默认使用合成输入，不纳入私人词表或个人学习文件。

初始化文档不代表 T0–T4 已通过；当前没有转换器、抓取器、词包或多语言运行时交付。
