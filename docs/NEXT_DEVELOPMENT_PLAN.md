## 2. 建议的开发顺序

下一批应用开发的明确清单为 N1–N4，先默认值／迁移，再设置外观与项目入口。P3／P4 是已有主线的质量与交付工作；H1 保留为后置开发。各阶段按实际缺陷和可用测试环境细化，本轮不开始功能实现。

| 顺序 | 归属／工作 | 完成标准 |
| --- | --- | --- |
| P1 | miancak：先修 N1／N2，统一默认值及迁移行为 | 在从未安装过应用的客体上，以两种正常启用顺序验证默认键面；宽窄屏及两个横屏方向、旋转／重启、手动更改和恢复默认均符合第 1 节。旧配置与学习保留，不以预写偏好代替首装 |
| P2 | miancak：修 N3／N4，统一设置样式、项目身份与文档入口 | N3 先保存可复现的对齐差异，再修同级 inset、图标占位、标题／摘要及自定义条目，用真实 APK 页面确认。N4 完成第 1.1 节的逐项盘点，修正主页／反馈链接、产品名称、翻译、现行指南和分发元数据，实际点击进入本仓库；保留上游归属 |
| P3 | miancak：中文输入与稳定性继续验收 | 以日常词句、多音词、人名、长句、多编辑器和可复现反馈建立增量用例；分别评估词包、引擎参数与个人学习。保留候选深项选择／过期结果、中文标点、完整 Fn KeyEvent、符号分页、编辑器和词表导入／部署／回滚回归。新发现的问题按复现结果修，不重写已稳定的布局模型 |
| P4 | miancak：形成可持续交付的版本 | 明确稳定签名与保管方式；用相同发布身份做真实版本覆盖升级，核对设置、键位、词表及学习数据的备份／恢复和回滚边界。完成可获得的 ARM 实机及目标编辑器测试，给出版本、哈希和实际限制；缺设备或旧签名不能写成通过 |
| 更后 H1 | miancak：高级手势规则编辑，先讨论再实现 | 在上述应用修复和交付基础稳定后，再确定独立顺时针／往返规则、继承／Shift 跟随／独立动作／禁用及文件兼容；不能将当前“做手势选择设置项”描述为这套新规则编辑已经完成 |
| 独立数据路线 D1–D4 | 通用词典转换／数据工具：规格、最小试点、再决定拆仓 | 沿用 [词典路线图](DICTIONARY_ROADMAP.md)；不阻塞 P1–P4，不把新增语言、纠错算法和数据转换捆成一次输入法改造 |

P3 是对已实现能力的持续验证与按需修复，不代表重新开发整套候选、编辑器或词表管理。词表导入兼容范围仍以 [RIME_WORD_TABLES.md](RIME_WORD_TABLES.md) 为准；不承诺任意 Rime 编码、无注音数据、Lua／模型或整套万象方案都能直接载入。个人短语管理、布局复制／命名等可以另列后续功能，当前不视为已确定的下一批工作。

当前 API 23 偶发虚拟管道／无障碍根丢失的根因仍未确认；同 APK 后续完整通过不抹去原失败。若再次发生，继续使用有界诊断区分宿主、客体和应用等待，不靠放大超时或删除断言将其变成成功。所有维护脚本继续有可配置的有限超时，默认 3600 秒。

每个实际变更阶段同步做相关单元与真实 APK 场景；最终再组合验证安装、升级、重启与恢复。保留原始失败和确切 APK 来源，不以键帽、预览或测试假设代替接收正文和功能事件。测试只使用合成输入；公开报告保留必要汇总，不把运行进程列表或个人学习数据作为默认公开附件。

## 4. 建议独立立项的内容

2026-10-27 进一步立项：现阶段拟创建一个 `rime-lexicon-tools` 工具仓库，转换与 MediaWiki 采集作为模块；`rime-lexicon-packs` 仅作后续条件性候选。具体范围、初始文件、里程碑与创建状态见 [独立项目方案](LEXICON_PROJECT_PLAN.md)。远程仓库本轮尚未创建，初始文档已准备为文件包；没有工具实现交付。

| 候选项目／模块 | 建议范围 | 与 miancak 的边界 |
| --- | --- | --- |
| 通用词典转换工具（优先候选） | 将可追溯的 cdict 上游源词表等转换为共同的 Rime 兼容源格式；处理编码／大小写／权重／重复、旁路元数据、来源／许可及确定性构建 | 先做 D1 格式契约和一个英语最小试点，再依据复用价值拆仓；不把 cdict 二进制改名，不与 Android View、手势或个人学习文件耦合。miancak 固定工具／词包版本并负责实际运行 |
| MediaWiki 等词源的采集与清洗工具 | 抓取／增量、清洗、去重、注音或编码、人工修正、来源和许可，输出可验证词表 | 获取和准备数据在工具侧；导入、输入及学习在应用侧。无法可靠注音的条目须明确列出，不静默混入当前显式拼音导入格式 |
| 可复用词包／数据发布仓库（按需要再拆） | 多词源／多语言的版本化词包、清单、来源、许可和自动校验 | 只有数据体量、更新频率或其它消费者形成实际需求时才拆；现阶段可保持固定上游引用。拆仓不等于每种语言另做输入法，也不自动更换当前默认词包 |

建议让转换与采集先作为同一个工具仓库的模块，避免一开始拆出多个难以协调的小仓库；词包数据是否再独立发布，等第一个可复用试点形成后决定。上一轮未创建仓库；本轮新增授权允许创建独立工具仓库并初始化文档，状态以 [独立项目方案](LEXICON_PROJECT_PLAN.md) 为准。

共同维护的目标是 UTF-8 Rime 兼容的 `.dict.yaml` 源文件，加独立的版本／来源／许可等元数据；schema 和输入算法配置另列。librime 编译产物与过渡 cdict 产物都是版本化生成结果，不能当成跨后端通用的词典文件。无法无损映射的字段必须说明，不以丢弃元数据换取“完全兼容”。

## 5. 保持的约束

- 布局 ID 决定输入策略；Fn 只往返明确配对变体，完整保留上游功能及实际 F1–F12 KeyEvent。
- 共享控制方向跨布局一致；符号面板可见 Fn 无特殊效果，栏目分页与 Shift 配对遵循现有契约。
