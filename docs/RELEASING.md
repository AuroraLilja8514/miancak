# APK 发布约定

2026-11-01 维护者要求：先发布当前最新版 APK，再继续 N1–N4 开发；开发完成后的正式发布同样通过 GitHub Releases。

普通 CI artifact 用于构建／测试，不作为正式发布入口。正式 APK 必须由本仓库 master 上的完整 MIANCAK CI 成功产物生成，使用已登记的同一发布证书，完成正式 APK 验收后写入 GitHub Release。版本标签不重定向，已发布文件不静默替换。

工作流分离无密钥的来源／版本／APK 检查、release-signing 环境中的最小签名步骤、无私钥的 API 23/35 验收、以及只具有发布权限的上传任务。签名步骤不 checkout 或运行应用 Gradle。它只运行已审查并内嵌于工作流的工具，固定 Android Build Tools 35.0.0，核对工具哈希、实际 APK 包名／版本、输入哈希与公开证书指纹，显式启用 v1/v2/v3 签名并验证 API 21 签名兼容性。

正式文件包括 APK、SHA256SUMS.txt、release-provenance.json。上传先进入 draft Release，只有三项文件的服务端哈希均匹配，才公开 Release。签名 job 无发布权限；发布 job 不持有私钥。Release 注明确切源码、版本号、CI／正式 APK 验收、签名身份和实际限制，不把临时测试签名的旧结果当成正式签名升级。

每次应用变更递增 versionCode 和 versionName，添加对应的 docs/releases/版本.md。同一版本已发布且应用构建输入完全相同的文档／流程提交会跳过重复发布；应用构建输入改变但版本未变则拒绝发布。

首次发布没有旧正式 APK，只能验证同版本重装；后续发布从上一 GitHub Release 取得正式 APK，验证同证书和递增版本后，执行真实的两版本覆盖安装。偏好／非空学习数据库在安装和真实重启前后核对，测试执行器使用独立 debug 证书，不接触正式私钥。

当前批准设置按维护者 2026-10-31 的决定关闭；工作流依旧限制 master 和完整 CI 来源。私钥用途仅限 miancak，密码不进入 Git、聊天、日志或公开产物。独立加密备份恢复与 ARM 真机验证不由模拟器或签名流程代替。
