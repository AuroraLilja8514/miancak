## 2. 已确认的布局与 Fn 规则

### 2.1 布局是唯一模式来源

- 当前布局 ID 确定语言、输入策略、按键定义与切换目标。不得再维护能与布局分离变化的全局中英文模式。
- 字面字符、引擎输入、功能键事件、编辑动作、光标滑动动作和布局跳转仍是不同动作类型。固定语言输入策略不妨碍按键明确输出数字、符号或 ASCII 文字。
- 每个快捷动作的目标保存在布局定义中；运行时按固定关系跳转，不依赖历史来路推断“返回哪里”。选择器同样使用配置后的明确目标集合。
- 需要不同语言归属或返回关系的辅助布局使用明确的布局实例；可共享按键模板，不从隐藏模式继承输入行为。
- Shift 锁定是修饰键状态，与布局定义分开；它不另外决定输入语言。

### 2.2 Fn 只切换当前布局与其配对变体

| 基础布局 | Fn 变体 | 变体按 Fn 后 |
| --- | --- | --- |
| 英文 QWERTY | 完整上游英文符号／功能布局 | 英文 QWERTY |
| 中文 QWERTY | 从完整上游 Fn 布局派生的中文符号／功能布局 | 中文 QWERTY |
| 希腊／数学 | 该布局自己的上游 Fn 替代字形／数学功能变体 | 希腊／数学基础布局 |
| 其他布局 | 仅使用明确配对的自身变体；未定义则不显示或禁用 Fn | 配对基础布局 |

基础布局与变体分别是可编辑布局。Fn 关系必须明确、双向且可校验；不得把拼音、注音、数字或其他任意辅助页直接指定为无关布局的 Fn 目标。从选择器直接进入 Fn 变体也应亮起 Fn；离开变体后状态随实际布局更新。

中英切换是固定布局跳转。例如中文基础布局对应英文基础布局，中文 Fn 变体对应英文 Fn 变体。发音文字布局返回中文的例外入口见第 4 节。

### 2.3 完整保留上游功能

后续首先形成上游与修改后逐槽位对照表：布局、行列、中心／方向、普通动作、Shift 动作、Fn 变体动作、隐藏 `loc` 定义及修改理由。

清单必须覆盖 F1–F10、上游 F11／F12 入口、Home／End／PageUp／PageDown、Insert、NBSP、撤销／重做、纯文本粘贴、货币／数学／替代字符及相关修饰组合。默认配置和升级不得无声丢失这些功能。用户可以主动改键，且程序升级应保留用户覆盖；重置时才恢复对应默认定义。

中文变体在完整基准上作明确的符号替换和补充。只使用真正未占用的槽位；隐藏位、正向位和已有手势入口都属于占用，不能因键面看起来空白而覆盖。

## 3. 可视化编辑必须覆盖真实动作空间

设置入口：布局 → 具体基础布局 → 对应 Fn 变体 → 编辑。选择器内直接选中变体后，设置中也应定位到同一布局定义。

| 位置 | 上游槽位 |
| --- | --- |
| 中心 | `key0` / `c` |
| 左上、右上、左下、右下 | `key1` / `nw`、`key2` / `ne`、`key3` / `sw`、`key4` / `se` |
| 左、右、上、下 | `key5` / `w`、`key6` / `e`、`key7` / `n`、`key8` / `s` |

要求：

1. 总览、详细编辑、Shift 预览、Fn 变体预览和实际键盘都呈现中心加八向。只使用四向的键可以空着其余位置；不能把正向动作画到斜向。
2. 显示实际继承结果，区分继承、清空和用户覆盖。支持对照基础／变体、保存／取消、按位置及整布局重置、导入导出。
3. 方向名称用于界面与无障碍说明，不只显示内部数字。空格和移动键必须有足够的预览空间，不能截断重要动作。
4. 动作选择器应覆盖真实动作类型。F1 必须存成功能键，光标滑动必须保留滑动语义，不能退化成文字或单次箭头事件。
5. 保留原始八向及手势配置的导入导出。仅修改普通或 Shift 动作时，不得丢掉尚未在编辑器展示的高级手势字段。
6. 原 `Layered` 键与 GESTURE 的组合需要专门核对：当前实现对非 Shift 修饰符会选普通层继续修改，可能绕开显式 Shift 层。后续必须明确继承／覆盖的求值顺序并测试，不能仅检查预览标签。

## 4. 空格、发音文字与符号入口

### 4.1 空格与发音入口

- 空格点击继续遵循组合状态：组词时确认候选，空闲时输出空格。左右光标滑动保留上游功能。
- 用户要求空格上下的含义一致。**待确认 Q1**：“一致”是两个方向执行同一个动作，还是在不同布局中保持同一套上下规则；统一的具体功能也尚未指定。本轮不擅自定为上一／下一布局或其他动作。
- 中文主布局空格左上作为发音文字入口的拟定位置，默认进入拼音文字布局；设置可改为以同一入口进入注音文字布局。
- 拼音或选定的注音文字布局，Shift 右上固定切回中文主布局。这是布局定义中的明确跳转，不改变隐藏语言状态，也不返回任意历史页面。
- 韵母与未选中的注音布局不需要各占主界面直达键。保留既有内容，按后续明确的内部子页／选择器设计提供访问；不能据此擅自删除页面。
- 发音入口与 Fn 独立。设置变更后写入确定的跳转关系，旋转、重建及升级后含义不变。

### 4.2 符号与宽度

- 英文／中文 Fn 符号功能变体保留全部上游功能。低频扩展符号布局可增加斜向位置、更多数学符号和其他不常用符号，不取代 Fn 基准。
- 扩展符号布局默认由选择器进入，无需占高频快捷位置；允许用户把空格左下等闲置位置设为入口。该候选位置不挤占左上发音入口、上下动作或左右光标滑动。
- 对符号布局中有全半角对应关系的字符，Shift 使用明确的全角／半角配对；逐项列出原字符、Shift 字符及无对应字符的行为。Fn 变体中的功能键、原有 Shift 组合和其他上游动作不得被一条全局宽度转换规则覆盖；没有对应字符的数学符号不能机械执行全角转换。
- 中文语义括号、引号与 Unicode 宽度转换分开定义。例如 `［］` 与 `【】` 不能混为同一对；字符规范化不能悄悄改变数学符号或用户正文。
- 此处的 Shift 配对仍遵循单指锁存／锁定操作，不把全半角新增为与布局脱离的隐藏模式。中文组词时明确字面符号继续按“确认候选后追加”提交。

## 6. 曲线／往返手势：现状与待定设计

### 6.1 当前识别方式

代码没有拟合抛物线。`Pointers.onTouchMove` 用滑动距离门限与相对按下位置的角度识别方向，内部将角度分为 16 个扇区，映射到八个动作槽位；空位会在邻近方向寻找可用动作，Slider 有更窄的匹配限制。

`Gesture` 识别结果包括：普通滑动、滑出再回中心的 Roundtrip、顺时针转向的 Circle、逆时针转向的 Anticircle。旋转不要求画出完整圆；取决于方向变化与 `circle_sensitivity`，也可能因转向反转被取消。

| 手势 | 当前用于求值的键 |
| --- | --- |
| 普通滑动 | 相应方向找到的动作 |
| 滑出再回中心 | 当前／最后识别方向找到的动作，再应用 GESTURE 修饰 |
| 顺时针转向 | 按键中心动作，再应用 GESTURE 修饰 |
| 逆时针转向 | 布局单独声明的 `anticircle` 动作，再应用已有修饰状态 |

在当前 `KeyModifier.apply_gesture` 中，先尝试 Shift 映射；如果动作改变就使用该结果。未改变时尝试 Fn 映射；仍未改变时再处理部分特殊动作，例如按词删除。因而它与 Shift 有关联，但不保证等于“先按 Shift 再点键中心”。例：普通 `a` 的顺时针手势通常得到 `A`；对方向数字 `1` 做往返，若 Shift 没有修改它，则可回退到 Fn 的 F1。已有修饰状态和自定义映射也会影响最终值。

`doc/Custom-layouts.md` 对自定义 Fn 优先级的描述与当前代码的 Shift 优先顺序存在需要核对的差异；后续以逐项实际结果和用户确认后的规则为准，同时修正文档，不能只照抄旧说明。

### 6.2 当前能设置什么

- 设置中已有滑动距离、环形手势灵敏度及环形禁用选项；这些影响识别，不等于逐键自定义输出。当前环形禁用通过方向变化阈值生效，滑出再返回中心仍可形成 Roundtrip，不能把它描述为禁用全部曲线／往返手势。
- XML 可用 `anticircle` 定义逆时针动作，`modmap` 的 Shift／Fn 映射可间接影响其他手势。
- 目前可视化编辑器没有独立的往返／顺时针／逆时针动作编辑入口；不能声称已经支持完整手势配置。

### 6.3 待讨论提案

**Q2：尚未确认采用。** 在每键“高级手势”中分别提供“继承上游”“跟随该位置的 Shift 动作”“指定独立动作”“禁用”；往返以方向槽位区分，顺时针以中心动作区分，逆时针沿用独立字段。默认保留上游规则。要选择动作时应预览最终结果与继承来源。

一旦 Fn 变成具名布局，GESTURE 仍是单次手势的动作变换，不允许顺势变成跨布局跳转。如何与 Fn 变体、显式 Shift 层、全半角配对求值，以及是否允许用户逐方向覆盖，需在实现前形成明确对照表。不能为了布局重构删掉当前的 Fn 回退输出。

## 7. 正式中文词包规划

1. 首个默认候选为[雾凇拼音](https://github.com/iDvel/rime-ice)的字表、基础词库及适量扩展词库；大型词库单独评估，不能以只导入 8105 字表代替完整词汇覆盖。
2. [万象的字词数据](https://github.com/amzxyz/rime-wanxiang)作为另一候选，使用其纯词表。带调编码、无注音词条和当前配置不支持的项目必须有可追溯处理方案，不得通过静默删词获得“兼容”。数据采用不要求安装完整第三方方案。
3. 固定版本、逐文件许可／来源／哈希、转换规则、重复与词频处理；保留原始数据。正式内置词包与用户导入共用验证及恢复边界，布局重构不得清空个人学习。
4. 用代表性日常聊天、工作表达、人名地名、多音词和长句比较首选／前几候选、切分和排序；候选词包确定后再设可量化验收标准。词表、引擎参数、个人学习和上下文能力分别记录，不以词条总数代替质量。
5. 在 Android 上记录冷启动、部署、内存、输入响应与离线恢复。此阶段不承诺未测过的 ARM 真机表现。跨语言共同源格式／cdict 迁移继续由 #18 独立跟踪。

本规划不引入或下载新的生产词典，也不把候选来源写成已经采用的正式默认。
