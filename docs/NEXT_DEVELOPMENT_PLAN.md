## 2. 建议的开发顺序

先推进 P0 稳定签名与保管基础；应用功能清单仍为 N1–N4，先默认值／迁移，再设置外观与项目入口。P3／P4 是已有主线的质量与完整交付工作；H1 保留为后置开发。截至 2026-10-29 已记录安全方案、优先级并登记维护者提供的公开证书；未接触正式私钥、配置 Secrets、修改应用／签名工作流或完成实际正式签名。

| 顺序 | 归属／工作 | 完成标准 |
| --- | --- | --- |
| P0（提前） | miancak：建立稳定签名身份与保管、验证实际签名及首轮覆盖升级 | 按 [稳定签名方案](SIGNING_PLAN.md) 在维护者可信电脑生成／备份专用私钥，登记公开证书指纹；CI 无正式密钥地构建，先本机签名并核验实际 APK。验证同包名、同签名和递增版本覆盖升级；旧 debug 到 release 的迁移单独说明。受保护自动签名按需要后接入 |
| P1 | miancak：先修 N1／N2，统一默认值及迁移行为 | 在从未安装过应用的客体上，以两种正常启用顺序验证默认键面；宽窄屏及两个横屏方向、旋转／重启、手动更改和恢复默认均符合第 1 节。旧配置与学习保留，不以预写偏好代替首装 |
| P2 | miancak：修 N3／N4，统一设置样式、项目身份与文档入口 | N3 先保存可复现的对齐差异，再修同级 inset、图标占位、标题／摘要及自定义条目，用真实 APK 页面确认。N4 完成第 1.1 节的逐项盘点，修正主页／反馈链接、产品名称、翻译、现行指南和分发元数据，实际点击进入本仓库；保留上游归属 |
| P3 | miancak：中文输入与稳定性继续验收 | 以日常词句、多音词、人名、长句、多编辑器和可复现反馈建立增量用例；分别评估词包、引擎参数与个人学习。保留候选深项选择／过期结果、中文标点、完整 Fn KeyEvent、符号分页、编辑器和词表导入／部署／回滚回归。新发现的问题按复现结果修，不重写已稳定的布局模型 |
| P4 | miancak：形成可持续交付的版本 | 沿用 P0 的稳定身份，持续做真实版本覆盖升级，核对设置、键位、词表及学习数据的备份／恢复和回滚边界。完成可获得的 ARM 实机及目标编辑器测试，给出版本、哈希和实际限制；P0 完成不代替这些结果，缺设备或旧签名不能写成通过 |
| 更后 H1 | miancak：高级手势规则编辑，先讨论再实现 | 在上述应用修复和交付基础稳定后，再确定独立顺时针／往返规则、继承／Shift 跟随／独立动作／禁用及文件兼容；不能将当前“做手势选择设置项”描述为这套新规则编辑已经完成 |
| 独立数据路线 | 具体词包复用／构建与 cdict 的 D1–D4 迁移分开推进 | 按 [修订项目方案](LEXICON_PROJECT_PLAN.md) 优先复用现有成果；具体词包不等待英语转换或通用工具，不阻塞 P0–P4 |

P3 是对已实现能力的持续验证与按需修复，不代表重新开发整套候选、编辑器或词表管理。词表导入兼容范围仍以 [RIME_WORD_TABLES.md](RIME_WORD_TABLES.md) 为准；不承诺任意 Rime 编码、无注音数据、Lua／模型或整套万象方案都能直接载入。个人短语管理、布局复制／命名等可以另列后续功能，当前不视为已确定的下一批工作。

当前 API 23 偶发虚拟管道／无障碍根丢失的根因仍未确认；同 APK 后续完整通过不抹去原失败。若再次发生，继续使用有界诊断区分宿主、客体和应用等待，不靠放大超时或删除断言将其变成成功。所有维护脚本继续有可配置的有限超时，默认 3600 秒。

每个实际变更阶段同步做相关单元与真实 APK 场景；最终再组合验证安装、升级、重启与恢复。保留原始失败和确切 APK 来源，不以键帽、预览或测试假设代替接收正文和功能事件。测试只使用合成输入；公开报告保留必要汇总，不把运行进程列表或个人学习数据作为默认公开附件。

## 4. 开源复用、具体词包与 cdict 的边界

2026-10-27 用户修正后的范围优先于前版“一个通用工具仓库＋以后 packs 仓库”的安排，详见 [修订项目方案](LEXICON_PROJECT_PLAN.md)。不建立通用 `rime-lexicon-packs`，也不预设必须创建通用工具平台；没有创建新仓库。

| 路线 | 采用方式／归属 | 边界 |
| --- | --- | --- |
| 现有 MediaWiki／其它 Rime 词表 | 优先采用已有词表或开源工具；已核对 mw2fcitx 与 fcitx5-pinyin-zhwiki 的 README | 先验证固定版本输出能否满足现有导入格式；只为确认的缺口作薄适配，不默认重写采集和生成器 |
| 我们额外构建并持续维护的具体词包 | 可按独立词源／主题建立仓库，包含配置、读音修正、过滤规则、固定依赖、来源／许可及构建与发布 | 不按每个文件拆仓库，不创建泛化 packs 汇总仓库；上游已有成果满足需求时不重复建 |
